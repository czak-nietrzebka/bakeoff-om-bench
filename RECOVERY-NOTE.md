# Recovery note — read this before trusting file history

On 28 August 2026 the working copy of this repository was destroyed: the entire
results package lived in a session-scoped scratch directory on the operator's
machine, that directory was recycled, and none of the four result commits had
been pushed. The only surviving remote state was the pre-registration commit.

**Everything here was rebuilt the same day from surviving evidence**, in order of
preference:

1. **Measurements** — re-fetched from the benchmark host's append-only ledgers
   (`data/runs/`, `data/journal/`, `data/judge/`), which were never at risk; the
   analysis script reproduces the published per-task table from them to the cent,
   which is the property the whole package was designed around.
2. **Documents and scripts** — reassembled from the raw payloads preserved in the
   session transcript and in the review agents' transcripts: file births, every
   subsequent edit (applied in order, each anchored on exact surrounding text),
   and full-file reads made by the final consistency check. Where two sources
   overlapped they agreed; where an edit's anchor was missing, the final-review
   read supplied the paragraph verbatim.
3. **Nothing was rewritten from memory.** Files with no surviving byte source were
   regenerated by their own generators over the recovered data and are labelled by
   their `generated_utc` fields (`data/usage-summary.json`, `data/SCRUB-REPORT.json`).

**What is different from the lost original:** commit hashes and commit history
(the four result commits are collapsed into this recovery commit); file mtimes;
possibly late-round copy-edits to prose paragraphs whose byte sources did not
survive — every number was re-verified against the raw records instead. macOS
resource-fork files (`._*`) that had shipped in the pre-registration commit were
removed here.

The failure itself is the same class this benchmark keeps measuring in its
subjects: a single unreplicated copy of finished work, kept in a location whose
lifecycle nobody had read, with publication deferred. It is logged in the logbook
as entry 27 and the practice has changed: the package now lives in a durable
working directory and every result lands on the remote the day it exists.
